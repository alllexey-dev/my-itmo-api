# Ошибки

Каждый метод либо возвращает данные, либо бросает `MyItmoException` (`dev.alllexey.itmoapi.core`). Проверять
коды ответа самому не нужно.

| Вид | Когда | Что делать |
|---|---|---|
| `Auth` | Нужен вход: неверный логин или пароль, ITMO.ID попросил дополнительный шаг (например, 2FA), сессия закончилась (HTTP 401, в My ITMO - после одной попытки обновить токен), сессии нет в хранилище или ITMO.ID отклонил refresh token. У `itmo.bars` - ещё и когда нет сессии БАРС ([bars.md](bars.md)) | Войти заново |
| `Api` | My ITMO вернул код ошибки: `errorCode` и HTTP-статус в `status` | Разобрать код; повтор обычно не поможет |
| `Http` | Неуспешный HTTP-статус без кода ошибки, в том числе 403: сессия действительна, но доступа к ресурсу нет | 5xx - повторить позже |
| `Network` | Сбой сети | Повторить позже |
| `Decode` | Ответ не удалось разобрать | Повторить позже; если повторяется - сообщить об ошибке |
| `Empty` | Сервер ответил успехом, но без данных, которые должен вернуть этот метод | Считать, что данных нет, или повторить позже |

```kotlin
suspend fun weekOrNull(itmo: MyItmo, monday: LocalDate): List<Schedule>? = try {
    itmo.schedule.getPersonalSchedule(monday, monday.plus(6, DateTimeUnit.DAY))
} catch (error: MyItmoException.Auth) {
    null // сессия закончилась: нужен новый вход
} catch (error: MyItmoException.Api) {
    null // My ITMO отказал: error.errorCode
} catch (error: MyItmoException) {
    null // Network, Http, Decode, Empty: можно повторить позже
}
```

Правила, на которые можно опираться:

- Библиотека сама никогда не удаляет сохранённую сессию, в том числе при `Auth`: хранилище меняют только
  успешный вход, обновление токена и `logout()`. Что делать после `Auth` - в
  [auth.md](auth.md#когда-сохранённая-сессия-перестала-работать).
- "Ничего нет" - не ошибка. Там, где сервер так отвечает, метод возвращает пустой список или `null`: например,
  `dormitory.getDormitoryStatus()` возвращает `null`, если заявки на общежитие нет, а `qr.getQrCode()` - если
  пропуска нет. Для остальных методов ответ без данных - это `Empty`: его можно отличить от нечитаемого ответа
  (`Decode`).
- Известные коды `Api` собраны в [spec/conventions.md](../spec/conventions.md#известные-коды-ошибок).

## Что нельзя писать в логи

В сообщениях исключений нет токенов, паролей и ответов сервера. Два поля сделаны доступными намеренно, и их
в логи писать не стоит:

- `MyItmoException.Api.serverMessage` - текст ошибки с сервера; он нужен, чтобы различать причины отказа;
- `MyItmoException.Network.cause` - исходная ошибка HTTP-движка, в ней могут быть данные запроса.

## Запись на спорт

`sport.signInLesson(id)` не бросает `MyItmoException`, а возвращает типизированный итог `SportSignResult`:
записан, мест нет, отказ или решения нет. Разбор итога с примерами - в [sport.md](sport.md).
