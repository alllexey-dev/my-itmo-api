# Спецификации

Пять файлов OpenAPI 3.1. Два основных - проверенные контракты, три остальных - исследование: схемы выведены из живых
ответов одного студенческого аккаунта и из кода клиентов.

| Файл | Что описывает | Операций | Как проверяется |
|---|---|---|---|
| [`my-itmo.yaml`](my-itmo.yaml) | my.itmo.ru: расписание, зачётка, учебный план, люди, физкультура, финансы, общежитие, бронирование, заявки, очереди, статус выбора дисциплин | 44 GET, 11 записей | Все GET сверены с живыми ответами через `verify:live`, последний прогон 2026-10-05; записи выполнялись вживую один раз и откатаны либо взяты из кода сайта, см. документы сервисов |
| [`bars.yaml`](bars.yaml) | БАРС: вход, пользователь, настройки, дисциплины, журнал студента | 6 GET | Все операции сверены с живыми ответами через `verify:live`, последний прогон 2026-10-05 |
| [`my-itmo-extra.yaml`](my-itmo-extra.yaml) | Дополнительные ручки my.itmo.ru: физкультура (отборы, проекты, экстернат, инструктажи, лимиты), навигатор, активности человека, заявки v2, общежитие, меню портала, факультативы, выбор дисциплин, справочники бронирования, очереди, практики, ГИА, соглашения, ассистент | 74 GET | Снято один раз (2026-10-05): схемы выведены из живых ответов и кода сайта; скрипт проверяет только соответствие сохранённых примеров схемам |
| [`bars-extra.yaml`](bars-extra.yaml) | Дополнительные студенческие ручки БАРС: дедлайны, личные настройки, планы контрольных точек, история оценок | 4 GET | Снято один раз: три ответа из четырёх пустые, их модели взяты из кода БАРС; скрипт проверяет только соответствие примеров схемам |
| [`itmo-services.yaml`](itmo-services.yaml) | Бэкенды вне прокси my.itmo.ru: загруженность помещений, расписание преподавателя, история зачётки, события и оценки, "Актуальное", клубы, достижения, помощь, обходной лист, текущий семестр | 26 GET | Снято один раз: ответы сняты вживую с токеном my.itmo.ru и совпали со схемой; скрипт проверяет только соответствие примеров схемам |

Что стоит знать:

- **Живая проверка основных контрактов** - это `npm run verify:live` в
  [itmo-mcp](https://github.com/alllexey-dev/itmo-mcp): скрипт вызывает каждую GET-операцию `my-itmo.yaml` и
  `bars.yaml` на реальном аккаунте и сверяет ответ со схемой. itmo-mcp хранит копию этих двух файлов и генерирует
  из них свой клиент, поэтому их пути, схемы и `operationId` меняются только согласованно с ним. Подробности -
  в [../sources.md](../sources.md).
- **Примеры.** В [`examples/`](examples/) лежат обезличенные живые ответы для операций трёх исследовательских файлов,
  по файлу `<operationId>.json`. Их проверяет `npm run examples` из [../tools/](../tools/): каждый пример должен
  соответствовать схеме ответа своей операции.
- **Образцы ответов основных ручек.** Для операций `my-itmo.yaml` и `bars.yaml` примеров в `examples/` нет. Их
  образцы - тестовые фикстуры библиотеки в [../../fixtures/](../../fixtures/): например
  [../../fixtures/schedule/personal.json](../../fixtures/schedule/personal.json),
  [../../fixtures/recordbook/](../../fixtures/recordbook/), [../../fixtures/bars/](../../fixtures/bars/). Они
  синтетические: написаны вручную по наблюдаемой форме ответов (кроме файлов с `error` в имени: это выдуманные
  ошибки для тестов).
- **Сессия БАРС.** Схема `barsSession` - `http`/`bearer`, а заголовок `authorization` из ответа `barsLogin` уже
  содержит `Bearer `. Сгенерированному клиенту передавайте значение без этого префикса; клиент, написанный вручную,
  отправляет значение заголовка обратно как есть.
- **"Observed empty".** Где ответ на проверочном аккаунте был пустым, модель взята из кода клиента; в схеме это
  помечено словами "Observed empty".
- **Один токен.** Бэкенды из `itmo-services.yaml` принимают токен my.itmo.ru. У каждого пути
  там своя запись `servers`: бэкенды живут на разных хостах.
- **Ссылки между файлами.** Исследовательские файлы ссылаются на основные по имени файла (`my-itmo-extra.yaml` и
  `itmo-services.yaml` - на `my-itmo.yaml`, `bars-extra.yaml` - на `bars.yaml`): держите все пять файлов в одной папке.
- **Неизвестные поля.** Схемы разрешают неизвестные свойства: сервер добавляет поля без предупреждения.

Ручки, которых нет в этих файлах, описаны в документах [../services/](../services/) таблицами со статусами. Как
добавить ручку в спецификацию: [../README.md](../README.md#как-дополнить). Вход и получение токена:
[../auth.md](../auth.md); конверты и ошибки: [../conventions.md](../conventions.md).

## Проверка

```bash
cd spec/tools
npm ci
npm run lint
npm run examples
```
